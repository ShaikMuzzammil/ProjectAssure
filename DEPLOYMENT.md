# ProjectAssure — Deployment Guide (v22)

End-to-end deployment instructions for the unified prototype (which includes the merged Host Control plane).

---

## Option A · Vercel (recommended — zero DevOps)

### 1. Prepare the repo

Push the **contents** of `prototype/` to the root of your GitHub repo's `main` branch:

```
my-repo/
├── src/
├── prisma/
├── public/
├── package.json
├── next.config.ts
├── tsconfig.json
└── ...
```

### 2. Import on Vercel

1. Go to [vercel.com/new](https://vercel.com/new).
2. Import the repo.
3. Framework preset → **Next.js** (auto-detected).
4. Build command: `next build` (default).
5. Output directory: leave default (`.next`).
6. Install command: `npm install --legacy-peer-deps` (add `--legacy-peer-deps` if you see peer conflicts).

### 3. Environment variables

| Variable | Required | Example | Notes |
|----------|----------|---------|-------|
| `DATABASE_URL` | yes | `postgresql://...` | Vercel Postgres or any external Postgres |
| `NEXTAUTH_SECRET` | yes | `openssl rand -base64 32` | Used for session signing |
| `HOST_CONTROL_ADMIN_EMAIL` | yes | `admin@projectassure.gov.in` | Admin login for `/host-control` |
| `HOST_CONTROL_ADMIN_PASSWORD_HASH` | yes | `pbkdf2$sha256$100000$...` | Generated by `src/lib/host/auth.ts` helper |
| `SMTP_HOST` | no | `smtp.gmail.com` | Real email outbox (else simulated) |
| `SMTP_USER` | no | `noreply@projectassure.gov.in` | |
| `SMTP_PASS` | no | `app-password` | |
| `SMTP_FROM` | no | `"ProjectAssure" <noreply@...>` | Display name + email |
| `NEXT_PUBLIC_APP_URL` | no | `https://myapp.vercel.app` | Used in email links |
| `NEXT_PUBLIC_HOST_URL` | no | `https://myapp.vercel.app/host-control` | Main app's link to host-control |

### 4. Database setup

After the first deploy:

```bash
# Local terminal (with DATABASE_URL set to your Vercel Postgres)
npx prisma db push --accept-data-loss
npx prisma generate
```

Vercel's filesystem is **read-only** in production. The host-control store gracefully degrades to in-RAM mode (no `.host-store.json` persistence) — for true cross-instance durability, use Vercel Postgres as the store backend (the `src/lib/host/store.ts` is already structured for this — replace the `loadPersisted` / `scheduleSave` calls with Prisma queries).

### 5. Verify

- `https://myapp.vercel.app/` → landing page (enhanced animated background visible after clicking Launch demo)
- `https://myapp.vercel.app/host-control` → host control login → admin dashboard
- `https://myapp.vercel.app/api/health` → `{ "ok": true }`
- `https://myapp.vercel.app/api/host/health` → `{ "ok": true }`

## Option B · Self-hosted (Docker)

### Dockerfile

```dockerfile
FROM node:20-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm ci --legacy-peer-deps

FROM node:20-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npx prisma generate && npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/public ./public
COPY --from=builder /app/prisma ./prisma
EXPOSE 3000
CMD ["node", "server.js"]
```

### Build & run

```bash
docker build -t projectassure:v22 .
docker run -p 3000:3000 \
  -e DATABASE_URL=postgresql://... \
  -e NEXTAUTH_SECRET=$(openssl rand -base64 32) \
  -e HOST_CONTROL_ADMIN_EMAIL=admin@projectassure.gov.in \
  -e HOST_CONTROL_ADMIN_PASSWORD_HASH=$(node -e "console.log(require('./src/lib/host/auth').hashPassword('changeme'))") \
  projectassure:v22
```

### docker-compose.yml (with Postgres)

```yaml
version: "3.9"
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: projectassure
      POSTGRES_USER: pa
      POSTGRES_PASSWORD: changeme
    volumes:
      - pa-pg:/var/lib/postgresql/data
    ports: ["5432:5432"]

  app:
    build: .
    depends_on: [db]
    environment:
      DATABASE_URL: postgresql://pa:changeme@db:5432/projectassure
      NEXTAUTH_SECRET: ${NEXTAUTH_SECRET}
      HOST_CONTROL_ADMIN_EMAIL: admin@projectassure.gov.in
      HOST_CONTROL_ADMIN_PASSWORD_HASH: ${HASH}
    ports: ["3000:3000"]

volumes:
  pa-pg:
```

## Option C · On-prem (PM2 + Nginx + Postgres)

For a single-VM deployment (e.g., NIC cloud, university lab server):

```bash
# 1. Install Node 20+, Postgres 14+, Nginx, PM2
# 2. Clone repo
git clone <repo> /opt/projectassure
cd /opt/projectassure
npm install --legacy-peer-deps
npx prisma generate
npx prisma db push --accept-data-loss
npm run build

# 3. Start with PM2
pm2 start "node .next/standalone/server.js" --name projectassure
pm2 save
pm2 startup

# 4. Nginx reverse-proxy (port 80 → 3000)
cat > /etc/nginx/sites-available/projectassure <<'EOF'
server {
    listen 80;
    server_name projectassure.gov.in;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
EOF
ln -s /etc/nginx/sites-available/projectassure /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

## Smoke tests (post-deploy)

```bash
APP=https://myapp.vercel.app

# Health
curl -s $APP/api/health | jq .          # → { ok: true }
curl -s $APP/api/host/health | jq .     # → { ok: true }

# Main app login (demo persona)
curl -s -X POST $APP/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"ananya.k@nic.in","password":"demo1234"}' | jq .

# Host control login (admin)
curl -s -X POST $APP/api/host/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@projectassure.gov.in","password":"changeme"}' | jq .

# Sync state
curl -s $APP/api/host/admin/sync | jq . | head -30

# Pages render
for path in "/" "/host-control" "/#/app/tracking" "/#/app/india-map"; do
  code=$(curl -s -o /dev/null -w "%{http_code}" "$APP$path")
  echo "$path → $code"
done
```

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| Build fails with `Module not found: xlsx` / `jspdf` | Run `npm install --legacy-peer-deps` (these are dynamic imports, must be installed) |
| `ENOENT: no such file or directory, open '.next/next-server.js.nft.json'` | This was the v21 bug — v22 fixes it by removing the `output: 'standalone'` override in `next.config.ts`. If you still see it, delete `.next/` and rebuild. |
| Host control 401 unauthorized | `HOST_CONTROL_ADMIN_PASSWORD_HASH` must be generated using `src/lib/host/auth.ts`'s `hashPassword()` helper — plain text will not work. |
| India map blank | Leaflet is loaded client-side via CDN. If your deployment blocks `unpkg.com`, switch the URLs in `src/components/projectassure/views/india-map-view.tsx` to a self-hosted copy in `/public/leaflet/`. |
| Vercel: `Module not found: addManualUser / getState / etc.` | These were phantom imports from removed v21 routes. v22 has them all removed; if you see them, you have stale route files in `src/app/api/host/admin/` — delete anything not in the v22 file list. |
| Prisma client not generated | Add `"postinstall": "prisma generate"` to `package.json` (already in v22). On Vercel, this runs automatically. |
| Login button hangs | Check the `NEXTAUTH_SECRET` is set and at least 32 chars. |
| Email not sending | Without `SMTP_HOST` set, the app simulates sends (visible in the host-control outbox). For real SMTP, set `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`. |

## Rollback

Vercel keeps every deployment. To roll back:
1. Vercel dashboard → your project → Deployments
2. Find the last known-good deployment
3. `⋯` → **Promote to Production**

For Docker / on-prem: keep the previous image tagged, `docker stop projectassure && docker run ... projectassure:v21`.
